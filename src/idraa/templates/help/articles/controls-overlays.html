What is a control?

A control is any security measure, process, or technology that your organisation has in place (or is considering). In Idraa each control has a yearly cost and one or more FAIR-CAM sub-functions that describe which part of the attack lifecycle the control addresses.

FAIR-CAM groups sub-functions into three families (LEC / VMC / DSC). See FAIR-CAM sub-functions for the full taxonomy.

How controls reduce modelled risk

When you attach a control to a scenario and run an analysis, Idraa passes your control assignments to the FAIR-CAM engine. The engine applies multipliers to Threat Event Frequency (TEF), Vulnerability and loss magnitude (response controls act on Primary and Secondary Loss) inside the Monte Carlo simulation — each iteration of the simulation draws from distributions shaped by those multipliers. Two rules change how response controls are credited (a detection dependency, and currency-valued loss reductions); they are set out in the control model.

This means controls reduce modelled risk in the simulation output, producing a lower residual loss distribution compared with the uncontrolled (inherent) baseline.

Important: controls do not change the inherent Vulnerability input

The Vulnerability you author in the scenario wizard is your estimate of the inherent probability that an attack attempt succeeds before counting your controls. Attaching controls does not overwrite that number — the engine applies a separate multiplier during the simulation so that you always retain the inherent baseline for comparison. See FAIR methodology primer for the full explanation of inherent vs. residual risk.

Adding controls to a scenario

From any scenario detail page, open the Controls tab. You can attach controls you have already created in your controls library, or adopt controls from the curated Control Library. Once attached, the control appears in the scenario’s assigned-controls list and is included in every subsequent analysis run.

To create or manage controls, go to /controls. Analysts and Admins can create, edit, and deactivate controls; Reviewers have read-only access.

What is an overlay?

An overlay is a named, organisation-wide preset that you apply to a scenario draft in the scenario wizard. Overlays carry two multipliers — frequency multiplier and magnitude multiplier — and each wizard step applies only its own. On the Likelihood step, choosing an overlay under Prefill options scales the draft’s Threat Event Frequency (TEF) rows by the frequency multiplier. On the Impact step, it scales the Primary and Secondary Loss rows by the magnitude multiplier (the same factor for both). To get both effects, apply the overlay on both steps. Vulnerability is never scaled. A step offers an overlay only when that step’s multiplier is not 1.0.

Typical use-cases include:

  • A macro threat-environment adjustment (e.g., elevated nation-state activity this quarter).
  • An organisation-wide adjustment to loss magnitude, such as a sector with unusually high incident costs.
  • An uplift for a high-risk period such as a merger or system migration (the scaled values stay in the scenario, so re-estimate it when the period ends).

Applying an overlay edits the values in your draft; it does not link the scenario to the overlay, and the values you end up with are yours to edit. Choosing the same overlay again on the same step compounds, because that step’s rows are scaled again. Nothing multiplies at run time: a run uses the scenario’s stored distributions, and runs do not record overlays. Controls are applied separately, inside the simulation, to whatever values the scenario stores.

To create or manage overlays, go to /overlays. Only Admins can create, edit, or deactivate overlays; other roles have read-only access.
